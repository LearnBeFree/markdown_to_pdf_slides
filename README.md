# Генератор слайдов: Markdown → PDF

Детерминированный конвейер для превращения заметки Obsidian (или любого
Markdown-файла) в презентацию: **Pandoc → Typst/Touying → PDF**. Никакой
ручной вёрстки: структура markdown определяет слайды, тема сама раскладывает
текст и картинки, а при проблемах (нет картинки, кривой шрифт) — не падает,
а деградирует аккуратно.

## Установка

Нужны: **pandoc** (3.x), **typst** (0.14+), **git** (клонировать и
авто-обновляться). Если pandoc/typst не установлены — команда `slides`
сама это заметит и напечатает инструкции для вашей ОС. Опционально:
**poppler** (`pdfinfo`) — тогда вотчер показывает число страниц.

```bash
git clone <адрес-этого-репозитория> slides_generator
cd slides_generator
./install.sh        # ставит команду `slides` в ~/.local/bin (или ~/bin)
slides build example.md
```

`install.sh` кладёт маленькую обёртку в `~/.local/bin` — без root, без
правки системных файлов. Если каталога нет в PATH, установщик напечатает
готовую строку `export PATH=…` для `~/.bashrc`. Обновление темы — `git
pull` в каталоге проекта (вотчер и сам проверяет обновления при старте).

**Windows**: поставьте [Git for Windows](https://git-scm.com) +
[pandoc](https://pandoc.org/installing.html) +
[typst](https://github.com/typst/typst/releases), откройте **Git Bash** и
выполните те же команды — все скрипты обычные bash, установка идентична.

## Использование

```bash
slides build my_doc.md                  # PDF рядом с исходником
slides watch my_doc.md                  # авто-пересборка при изменениях
slides watch my_doc.md выход/           # PDF в указанный каталог
slides watch my_doc.md выход/слайды.pdf # или в конкретный файл
```

Никаких временных файлов в рабочем каталоге: промежуточный `.typ`
пишется в системный temp (`/tmp`, `$TMPDIR` на macOS, `%TEMP%` на
Windows) и удаляется после сборки; рядом с исходником остаётся только `.pdf`.
Для отладки генерируемого Typst: `SLIDES_KEEP_TYP=1 slides build дека.md`
оставит `.typ` рядом с исходником. Вотчер хранит логи сборки тоже в
системном temp.

### Вотчер

При запуске `slides watch`:

1. **Проверяет обновления темы**: если у репозитория настроен remote
   `origin` и на нём есть новые коммиты — подтягивает их
   (`git pull --ff-only --autostash`). Нет remote / нет сети — предупреждает
   и работает локальной версией.
2. **Проверяет шрифты** и предупреждает об отсутствующих (сборка не
   ломается — тема подставляет запасные).
3. Следит за **исходником и всеми картинками, на которые он ссылается**
   (обложка и Obsidian-вставки включительно); изменение любого →
   пересборка, ошибки компиляции печатаются в терминал.

Останов — `Ctrl+C`. Интервал опроса: `WATCH_INTERVAL=0.3 slides watch дека.md`.

## Синтаксис деки

### Frontmatter (всё необязательно)

```yaml
---
title: Готическая архитектура # заголовок титульного слайда
subtitle: От Сугерия до пламенеющей # подзаголовок
author: Имя Автор
date: 2026
institution: Университет
accent-color: "#2c3e50" # акцентный цвет (hex, с # или без)
title-font: Oswald # шрифт заголовков (см. «Шрифты»)
body-font: Philosopher # шрифт текста
cover-image: assets/cover.jpg # фото на титульный слайд (затемняется)
toc: false # скрыть слайд-оглавление (по умолч. есть)
aspect-ratio: "16-9" # формат "W-H"; кривое значение → 16-9
lang: ru # язык (переносы, кавычки); по умолч. ru
---
```

### Структура

| Markdown                               | Что получается                                  |
| -------------------------------------- | ----------------------------------------------- |
| `# H1`                                 | слайд-разделитель (крупный заголовок по центру) |
| `## H2`                                | новый слайд с заголовком                        |
| `### H3` и глубже                      | жирный абзац внутри текущего слайда             |
| `---` (горизонтальная линия)           | следующий слайд с тем же заголовком             |
| обычный текст, списки, таблицы, цитаты | тело текущего слайда                            |

Слайд с длинным текстом автоматически ужимает шрифт (20pt → 14pt); если и
этого мало — печатается как есть.

### Картинки

- Одиночная картинка абзацем: портретная встаёт колонкой сбоку, альбомная —
  полосой снизу. Подпись — alt-текст или caption:
  `![Подпись](photo.jpg)`.
- **Две и больше картинок подряд** (каждая — отдельным абзацем) → слайд-галерея:
  движок сам подбирает сетку и масштаб, подписи всегда остаются на слайде.
- Работают Obsidian-вставки: `![[photo.jpg]]`.
- Пути — относительно файла деки; пробелы и `[ ] ` в именах допустимы
  (`![cap](<my pic.png>)` или `my%20pic.png`).
- Несуществующая/битая картинка → пунктирная заглушка со списком имени и
  предупреждение в stderr, сборка продолжается.

### Экранирование для продвинутых

Блок ` ```{=typst} … ` вставляется в генерируемый файл как есть —
можно вызвать любую функцию темы (`#focus-slide[Важно!]` и т.п.). Внимание:
опечатка в таком блоке — это ошибка компиляции, она честно укажет на строку.

## Шрифты

Порядок поиска: **(1)** папка `fonts/` проекта — она передаётся typst через
`--font-path`, **(2)** системные шрифты ОС.

- В комплекте: **Oswald** (заголовки) и **Philosopher** (текст) — их не
  нужно устанавливать в систему.
- Если в frontmatter указан шрифт, которого нет ни в `fonts/`, ни в системе
  (например, `title-font: Montserrat` без установки Montserrat) — сборка
  **не падает**: typst берёт следующий из запасной цепочки темы
  (Liberation → системные sans/serif). Вотчер об этом предупредит при старте.
- Свой шрифт: положите `MyFont.ttf` в `fonts/` и укажите
  `title-font: MyFont` во frontmatter.

## Устранение неполадок

| Симптом                                           | Причина / что делать                                                                                     |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `typst: command not found`                        | typst не в PATH (на Windows — положить `typst.exe` в PATH и перезапустить Git Bash)                      |
| `pandoc: YAML parse exception` (код 64)           | сломан frontmatter — проверьте `---` и отступы в YAML                                                    |
| `WARNING: skipping image …`                       | картинка не найдена/не картинка/не совпадает расширение — поставлена заглушка                            |
| ошибка `unclosed delimiter` с указанием строки    | опечатка внутри блока ` ```{=typst} `                                                                    |
| PDF не открывается в просмотрщике во время сборки | вотчер пишет новый файл поверх старого; большинство просмотрщиков это переживают, zathura — без вопросов |
