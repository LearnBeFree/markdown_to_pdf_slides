# AGENTS.md

Markdown → PDF slide generator: `slides` (bash CLI) → `build.sh` → Pandoc (`template.typ` + `theme-filters.lua` + `image-probe.lua`) → Typst/Touying (`slides-theme.typ`) → PDF. No lint, no CI; the test harness in `tests/` is the regression net.

## Verification

- `./tests/run.sh` is the primary check: it stages every deck in `tests/decks/` into `tests/.work/`, builds with `SLIDES_KEEP_TYP=1`, and diffs the generated `.typ`, normalized stderr, and PDF page count against `tests/golden/`. `./tests/run.sh -u` regenerates goldens after an INTENDED behavior change; never run `-u` just to make a failing diff go away. Marker files next to a deck: `<name>.md.crlf` (stage with CRLF endings), `<name>.md.bom` (prepend UTF-8 BOM), `<name>.md.fail` (build must fail; first line = grep -E pattern for stderr). Test images are byte-stable, generated by `tests/make-assets.sh`.
- `./build.sh example.md` (or `slides build example.md`) remains the smoke test — it must compile clean. `example.pdf` is committed, so a rebuild shows up in `git diff`; don't commit it as a side effect.
- Debug generated Typst: `SLIDES_KEEP_TYP=1 ./build.sh deck.md` keeps the intermediate `.typ` (plus theme copy) next to the source.
- Pinned toolchain: Typst 0.14–0.15, Touying 0.7.4 (see imports in `slides-theme.typ` / `template.typ`), Pandoc 3.x.

## Pipeline contract (spans 3 files — change together)

`theme-filters.lua` converts the Pandoc AST into explicit theme function calls (`title-slide`, `section-slide(...)` with optional `background-image`, `content-slide(...)` with an `images: (...)` tile list, `focus-slide`, `gallery-slide`, `toc-slide`). `slides-theme.typ` defines those functions and the deterministic tile-layout engine. Slides are NEVER created by Typst headings — the Lua filter fully owns content grouping (H1 = divider, H2 = new slide, EMPTY H2 = focus slide, a LONE image paragraph directly under H1/H2 = that slide's full-bleed background while TWO OR MORE image paragraphs under a heading are a gallery — none may be hijacked as a background, captions would be lost, `---` = slide split, H3+ = bold paragraph). The H1 divider is emitted DEFERRED (pending_section) because its background is only known after the following image paragraphs. Renaming a theme function or its `background-image`/`background-format` params breaks the filter, and vice versa; typst call syntax is `#slide(args)[body]` — args BEFORE the content block.

Images are a TWO-PASS pipeline: `image-probe.lua` dumps every AST image src (+ the frontmatter cover) to stdout; `build.sh` resolves each ref in bash (percent-decode, extension probing for Obsidian's `![[photo]]`, subtree search for shortest-path links, magic-byte sniffing) and hands `image-map` / `missing-images` to `theme-filters.lua` via a **YAML `--metadata-file`** (`image-map: [[src, path, fmt], …]`, `missing-images: [[src, why], …]`) — a FILE, not argv: on Windows MSYS may rewrite path-looking arguments, and big decks would hit the 32 KiB CreateProcess limit. Two traps bit us here and are load-bearing: (1) pandoc parses metadata-file strings as MARKDOWN INLINES, so every field is percent-encoded byte-wise by bash (`enc()`) and decoded in Lua (`pct_decode`) — a raw `king_of_assyria.jpg` key would come back emphasis-mangled and silently miss the map; (2) records must be buffered per section and concatenated after the loop — interleaved found/missing refs must never share one YAML key (duplicate keys silently drop earlier records). The filter does NO filesystem I/O and emits `#image(path, format: ...)` so extensions never matter. Any change to the record encoding must update BOTH build.sh and theme-filters.lua. `SLIDES_DEBUG=1` traces every resolution decision (fonts, images, the typst invocation) — ask for that log first in bug reports, especially from Windows.

`template.typ` is the Pandoc standalone template: frontmatter variables are conditionally interpolated (empty values would crash touying's `config-info` — keep the `$if(...)$` guards). `cover-image` arrives as an escaped raw string, `cover-format` as the sniffed format for the title-slide cover, `focus-accent` as the second accent color.

## Hard invariants (each guards a real past bug)

- `---` in markdown must mean ONLY a slide break. The awk block in `build.sh` is a single-pass NORMALIZER + frontmatter lifter: strips BOM/CRLF, tolerates blank lines before the leading `---`, only lifts the block if it is YAML-shaped (a leading non-YAML `---` block stays verbatim body), inserts a blank line before any body `---` that follows a non-blank line (kills the setext trap; fence-aware), and writes frontmatter via `--metadata-file`; pandoc runs with `-yaml_metadata_block`. Don't re-enable pandoc YAML parsing: a `---` block mid-deck would abort the build ("could not find expected ':'") or silently swallow slide text into metadata. The pandoc READER SPEC (identical in BOTH passes — probe and main; a mismatch desyncs the image manifest) additionally disables `blank_before_header` (a `## H` right after a text line or a `---` is a real heading) and `multiline_tables`+`simple_tables` (dashed `---` borders must never read as a table and swallow whole spans of slides — a real past bug found by the meso deck); pipe tables stay enabled.
- The frontmatter-stripped deck copy (`.slides-deck.*`, created by the awk block in `build.sh`) must stay NEXT TO THE SOURCE: `image-probe.lua` and bash resolve relative image paths against the input file's directory, so moving it into `$WORK_DIR` silently breaks deck-relative images. It is removed by the EXIT trap.
- The setext trap (a `---` directly after a text line turning it into a slide title) is neutralized by the normalizer, which inserts the missing blank line itself (fence-aware). `===` setext H1s still work; `---` setext H2s are gone by design.
- Missing/broken images degrade to dashed placeholders — the build never fails on them. All filesystem probing lives in bash (Unicode-safe on Windows, where pandoc's Lua `io.open` sees only the ANSI code page); the main Lua filter is pure AST→Typst and receives pre-verified results via metadata argv.
- Typst gets ONE root containing the .typ, theme, and all images: the build stages the generated `.typ` in a temp dir with a sibling copy of `slides-theme.typ`, emits image paths as absolute, and compiles with `--root /` (Windows: deck's drive root, drive prefix stripped from emitted paths).
- Windows Git Bash is a first-class target. No inotify, no absolute theme imports/env vars (both mangle non-ASCII Windows paths).
- Fonts resolve from repo `fonts/` (via `--font-path`) before system fonts; missing fonts fall back inside the theme, never fail the build. typst matches FAMILY names declared inside the font file, NOT filenames (`TapeBold.ttf` declares family `Tape`) — the build's check reports the real family name (isolating the file in a temp dir and asking `typst fonts --ignore-system-fonts`, which still lists typst's embedded fonts — subtract that baseline) when a frontmatter font misses.
